# DESIGN FOUNDATION

## Objetivo

Este documento define los fundamentos permanentes del diseño de VIMDY.

No describe pantallas específicas.

No describe componentes individuales.

Define las reglas que garantizan que todo el ecosistema mantenga la misma identidad, calidad y coherencia con el paso del tiempo.

---

# Filosofía

El diseño de VIMDY no busca llamar la atención.

Busca desaparecer.

Cuando el usuario trabaja,

debe pensar en su negocio,

no en el software.

La mejor interfaz es aquella que se vuelve invisible.

---

# Los Cinco Pilares

Todo diseño dentro de VIMDY debe respetar estos pilares.

## 1. Claridad

La información importante siempre aparece primero.

Nada compite por atención.

Todo tiene una jerarquía evidente.

---

## 2. Simplicidad

Cada elemento debe justificar su existencia.

Si puede eliminarse sin afectar la operación,

debe eliminarse.

---

## 3. Consistencia

Un mismo problema siempre se resuelve de la misma manera.

Los patrones nunca cambian entre módulos.

La memoria del usuario es sagrada.

---

## 4. Rapidez

Todo el sistema debe sentirse inmediato.

Las animaciones nunca retrasan la interacción.

Cada acción debe producir una respuesta instantánea.

---

## 5. Confianza

El usuario nunca duda del sistema.

Si VIMDY dice que una venta fue registrada,

esa venta existe.

Si muestra un inventario,

es el inventario real.

---

# Principios Visuales

Menos elementos.

Más espacio.

Menos color.

Más contraste.

Menos decoración.

Más información.

---

# Principios de Interacción

Cada pantalla tiene una intención.

Cada clic tiene un propósito.

Cada mensaje tiene utilidad.

Cada acción genera una respuesta clara.

---

# Principios de Arquitectura

Todo componente debe ser:

Reutilizable.

Escalable.

Independiente.

Predecible.

Nunca duplicar lógica.

Nunca crear variantes innecesarias.

---

# Evolución

VIMDY puede crecer.

Pero nunca complicarse.

Cada nueva función debe hacer al sistema:

Más simple.

Más rápido.

Más útil.

Si no cumple al menos uno de estos tres objetivos,

no entra al producto.

---

# La Prueba del Tiempo

Todo cambio debe responder esta pregunta:

"¿Este diseño seguirá sintiéndose moderno dentro de diez años?"

Si la respuesta es no,

el cambio debe replantearse.

No seguimos tendencias.

Construimos un estándar.

---

# La Prueba del Restaurante Lleno

Antes de aprobar cualquier cambio,

debe responderse esta pregunta:

Viernes.

8:30 PM.

Restaurante lleno.

80 pedidos activos.

Clientes esperando.

¿El usuario puede completar la tarea en menos de tres segundos?

Si la respuesta es no,

el diseño falla.

---

# La Regla de la Captura

Toda pantalla debe verse sólida incluso en una captura estática.

Sin animaciones.

Sin movimiento.

Sin efectos.

Si una captura transmite orden,

claridad

y confianza,

el diseño está bien construido.

---

# La Regla del Silencio

El software nunca presume.

Nunca distrae.

Nunca interrumpe.

Solo aparece cuando realmente aporta valor.

---

# Regla Suprema

El diseño no existe para impresionar.

Existe para que el negocio funcione mejor.

Si una decisión mejora la estética pero empeora la operación,

se rechaza.

Siempre gana la operación.
