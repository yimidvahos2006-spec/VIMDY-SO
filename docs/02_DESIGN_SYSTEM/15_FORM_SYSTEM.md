# FORM SYSTEM

## Objetivo

Los formularios permiten crear, editar y actualizar información.

Nunca deben sentirse largos.

Nunca deben parecer burocráticos.

Completar un formulario debe ser tan natural como mantener una conversación.

---

# Filosofía

Un formulario existe para ayudar al usuario a terminar una tarea.

No para hacer preguntas innecesarias.

Todo campo debe justificar su existencia.

---

# Principios

Los formularios siempre deben ser:

• Simples

• Rápidos

• Claros

• Consistentes

• Tolerantes al error

---

# Estructura

Todo formulario sigue este orden.

────────────────────────

Título

Descripción

Campos

Acciones

────────────────────────

Nunca cambiar este patrón.

---

# Longitud

Ideal

3–6 campos

Máximo recomendado

10 campos

Si supera los 10,

debe dividirse en pasos.

---

# Organización

Agrupar información relacionada.

Ejemplo

Información General

Nombre

Teléfono

Correo

────────────

Información Comercial

NIT

Dirección

Ciudad

---

# Etiquetas

Siempre visibles.

Siempre arriba.

Nunca usar etiquetas flotantes.

Nunca ocultarlas.

---

# Campos Obligatorios

Solo cuando sea realmente necesario.

Indicador

*

Color

#EF4444

Nunca abusar de los campos obligatorios.

---

# Validación

La validación ocurre mientras el usuario escribe.

Nunca esperar al botón Guardar.

Los errores deben aparecer cerca del campo.

---

# Mensajes

Incorrecto

Campo inválido.

Correcto

Ingresa un correo electrónico válido.

Incorrecto

Error.

Correcto

Falta seleccionar una mesa.

---

# Guardado

Los cambios deben guardarse:

Instantáneamente

o

Con un único botón principal.

Nunca usar varios botones de guardar.

---

# Botones

Solo dos.

Primario

Guardar

Secundario

Cancelar

Nunca tres acciones importantes.

---

# Navegación

ENTER

Siguiente campo.

TAB

Campo siguiente.

SHIFT + TAB

Campo anterior.

ESC

Cancelar (cuando aplique).

---

# Campos Inteligentes

Siempre que sea posible:

Autocompletar

Recordar valores anteriores

Sugerir información

Reducir escritura manual

---

# Estados

Todo formulario soporta:

Default

Loading

Editing

Success

Error

Disabled

Read Only

---

# Loading

Mientras guarda:

Bloquear acciones.

Mostrar indicador discreto.

Nunca bloquear toda la pantalla.

---

# Success

Cerrar automáticamente.

Mostrar Toast.

Nunca mostrar ventanas diciendo:

"Guardado correctamente."

---

# Error

Explicar claramente:

Qué ocurrió.

Cómo solucionarlo.

Nunca mostrar errores técnicos.

---

# Responsive

Desktop

Dos columnas cuando sea posible.

Tablet

Una o dos columnas.

Mobile

Una columna.

Siempre.

---

# Accesibilidad

Todos los formularios deben permitir:

Teclado completo.

Lectores de pantalla.

Focus visible.

Orden lógico.

Contraste AA.

---

# Rendimiento

Nunca perder información escrita.

Si ocurre una falla,

los datos permanecen.

El usuario nunca vuelve a escribir todo.

---

# Regla Suprema

El usuario nunca debe pensar:

"¿Qué me falta?"

El formulario debe guiarlo de forma natural hasta terminar la tarea.
