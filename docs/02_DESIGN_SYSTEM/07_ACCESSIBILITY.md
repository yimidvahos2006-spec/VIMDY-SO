# VIMDY DESIGN SYSTEM
# 07 — ACCESSIBILITY

---

# Objetivo

La accesibilidad garantiza que VIMDY pueda utilizarse durante jornadas completas de trabajo sin generar fatiga visual, confusión o barreras de interacción.

No es una característica.

Es un requisito obligatorio.

---

# Filosofía

Una interfaz accesible es una interfaz mejor.

No diseñamos únicamente para usuarios expertos.

Diseñamos para cualquier persona que deba operar un negocio con rapidez y seguridad.

---

# Principio Fundamental

Todo usuario debe poder utilizar VIMDY sin esfuerzo innecesario.

El sistema debe adaptarse al usuario.

Nunca al contrario.

---

# Legibilidad

Todo texto debe ser fácil de leer.

Nunca utilizar:

• Fuentes decorativas.

• Letras condensadas.

• Texto demasiado pequeño.

---

# Contraste

Todo texto debe mantener un contraste alto.

Texto principal

#FFFFFF

Fondos

#09090B

#121215

#18181C

Nunca utilizar texto gris sobre fondos grises.

---

# Tamaños mínimos

Texto normal

14 px

Labels

11 px

Detalles

10 px

Nunca utilizar menos de 10 px.

---

# Tamaño de Objetivos

Todo botón debe poder presionarse fácilmente.

Área mínima

44 x 44 px

Especialmente en tablets.

---

# Color

Nunca utilizar únicamente color para comunicar.

Siempre acompañar:

Texto

Icono

Indicador

---

# Estados

Todo estado debe ser evidente.

Activo

Inactivo

Error

Éxito

Carga

Nunca depender solo del color.

---

# Navegación por Teclado

Toda la aplicación debe funcionar completamente utilizando teclado.

Tab

Shift + Tab

Enter

Escape

Espacio

Flechas

---

# Focus Visible

Siempre debe existir un indicador de foco.

Nunca ocultarlo.

Nunca eliminar outline sin reemplazarlo.

---

# Atajos

Los atajos deben acelerar el trabajo.

Nunca reemplazar funciones normales.

Ejemplos:

Ctrl + K

Buscar

Ctrl + N

Nueva venta

Esc

Cerrar modal

---

# Formularios

Cada campo debe tener:

Label

Placeholder

Mensaje de ayuda

Mensaje de error

Nunca depender solo del placeholder.

---

# Errores

Los errores deben explicar:

Qué ocurrió.

Cómo solucionarlo.

Nunca mostrar códigos técnicos.

---

# Tablas

Las tablas deben ser fáciles de recorrer.

Nunca saturar columnas.

Permitir navegación mediante teclado.

---

# Iconografía

Todo icono importante debe tener texto de apoyo.

Nunca confiar únicamente en símbolos.

---

# Animaciones

Si el usuario activa:

Reducir movimiento

Todas las animaciones desaparecen.

Solo permanece la información.

---

# Tiempo

Nunca limitar el tiempo para completar tareas importantes.

El usuario controla el ritmo.

---

# Audio

VIMDY no depende de sonidos.

Toda información importante debe ser visible.

---

# Confirmaciones

Nunca exigir doble confirmación innecesaria.

Solo para acciones críticas.

---

# Responsive

Desktop

Tablet

Mobile

Todos deben conservar la misma facilidad de uso.

Nunca reducir la accesibilidad por tamaño de pantalla.

---

# Fatiga Visual

Reducir el cansancio mediante:

Mucho espacio.

Buen contraste.

Pocas distracciones.

Tipografía limpia.

Animaciones discretas.

---

# Carga Cognitiva

Nunca obligar al usuario a memorizar procesos complejos.

El sistema recuerda.

El usuario trabaja.

---

# Inclusión

VIMDY debe poder ser utilizado por:

Personal nuevo.

Personal experimentado.

Adultos mayores.

Usuarios con poca experiencia tecnológica.

---

# Errores Prohibidos

❌ Texto pequeño.

❌ Contraste bajo.

❌ Botones diminutos.

❌ Focus invisible.

❌ Errores técnicos.

❌ Animaciones excesivas.

❌ Navegación imposible con teclado.

❌ Colores sin significado.

---

# Checklist

Antes de aprobar una pantalla verificar:

□ Todo el texto es legible.

□ El contraste es correcto.

□ Los botones tienen tamaño suficiente.

□ El teclado funciona completamente.

□ El foco es visible.

□ Los errores son claros.

□ El usuario no necesita memorizar procesos.

□ La pantalla puede usarse durante horas sin fatiga.

---

# Regla Suprema

La mejor accesibilidad es aquella que el usuario nunca nota.

Simplemente siente que trabajar con VIMDY es fácil.
