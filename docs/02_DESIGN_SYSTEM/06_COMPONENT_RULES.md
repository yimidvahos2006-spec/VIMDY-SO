# VIMDY DESIGN SYSTEM
# 06 — COMPONENT RULES

---

# Objetivo

Este documento define las reglas universales que gobiernan todos los componentes de VIMDY.

No importa quién programe.

No importa cuándo.

Todo componente debe comportarse exactamente igual.

---

# Filosofía

Los componentes son piezas reutilizables.

No son diseños independientes.

Cada componente pertenece al Sistema Operativo VIMDY.

Debe sentirse familiar sin importar la pantalla donde aparezca.

---

# Regla Principal

Todo componente debe cumplir tres condiciones:

• Ser claro.

• Ser consistente.

• Ser inmediato.

Si falla una de las tres, el componente debe rediseñarse.

---

# Identidad

Todo componente debe transmitir:

Calma.

Orden.

Precisión.

Nunca espectacularidad.

---

# Apariencia

Todos los componentes utilizan:

Bordes suaves.

Colores neutros.

Contraste alto.

Sin decoración.

---

# Bordes

Nunca utilizar bordes gruesos.

Borde oficial

1 px

Color

#27272A

Opacidad baja.

---

# Radios

Elementos normales

8 px

Tarjetas

12 px

Avatares

Circular

Nunca radios exagerados.

---

# Sombras

Prohibidas.

Las capas se diferencian mediante:

Color.

Espacio.

Contraste.

Nunca mediante sombras grandes.

---

# Hover

Siempre responde.

Nunca exagera.

Solo cambia:

Color

Borde

Fondo

Nunca cambia tamaño de forma evidente.

---

# Active

Debe sentirse firme.

No agresivo.

Respuesta inmediata.

---

# Disabled

Reduce contraste.

Nunca desaparece completamente.

Debe seguir siendo entendible.

---

# Focus

Siempre utiliza

VIMDY Blue

#38BDF8

Nunca glow.

Nunca anillos enormes.

---

# Componentes Clicables

Siempre muestran respuesta inmediata.

El usuario nunca debe preguntarse si hizo clic.

---

# Componentes Informativos

Nunca parecen botones.

Nunca generan confusión.

---

# Botones

Solo existen tres niveles.

Primario

Secundario

Destructivo

Nada más.

---

# Tarjetas

Las tarjetas no son decoración.

Son contenedores de información.

Siempre mantienen:

Padding uniforme.

Jerarquía clara.

Mucho aire.

---

# Inputs

Todos los campos siguen la misma estructura.

Label

↓

Input

↓

Ayuda

↓

Error

Nunca alterar este orden.

---

# Selectores

Nunca abrir listas gigantes.

Siempre priorizar búsqueda.

---

# Checkboxes

Solo cuando existan múltiples opciones.

Nunca sustituir botones.

---

# Switch

Solo para activar o desactivar estados.

Nunca ejecutar acciones.

---

# Badges

Solo representan estado.

Nunca decoración.

---

# Toast

Siempre aparece abajo.

Nunca bloquea la pantalla.

Nunca necesita cerrarse manualmente.

---

# Modal

Debe resolver una tarea puntual.

Si un modal necesita scroll largo, debe convertirse en pantalla.

---

# Drawer

Solo para edición rápida.

Nunca para procesos largos.

---

# Tablas

Priorizar lectura.

Nunca demasiadas columnas.

Nunca parecer Excel.

---

# KPIs

Un KPI responde una pregunta.

Nunca varias.

---

# Iconos

Siempre ayudan.

Nunca adornan.

Si un icono puede eliminarse sin perder significado, debe eliminarse.

---

# Estados Vacíos

Toda pantalla vacía debe responder:

¿Qué pasó?

¿Qué puedo hacer ahora?

Nunca dejar al usuario frente a un espacio vacío.

---

# Estados de Error

Explican:

Qué ocurrió.

Qué hacer.

Nunca muestran códigos técnicos.

---

# Estados de Éxito

Discretos.

Breves.

No interrumpen.

---

# Consistencia

Si existe un botón Guardar en una pantalla,

Guardar debe verse exactamente igual en todas.

---

# Reutilización

Nunca crear un componente nuevo si uno existente puede resolver el problema.

---

# Errores Prohibidos

❌ Dos botones primarios.

❌ Colores diferentes para la misma acción.

❌ Bordes diferentes.

❌ Radios distintos.

❌ Animaciones distintas.

❌ Componentes con comportamientos diferentes.

❌ Inputs inconsistentes.

❌ Modales distintos.

---

# Checklist

Antes de aprobar un componente verificar:

□ Cumple la identidad VIMDY.

□ Es reutilizable.

□ Es consistente.

□ Tiene estados completos.

□ Es accesible.

□ Funciona con teclado.

□ Responde inmediatamente.

□ No necesita explicación.

---

# Regla Suprema

El usuario nunca debe aprender un componente dos veces.

Si aprendió a usarlo una vez,

podrá usarlo en cualquier parte de VIMDY.
